# Revelation Context Explorer

## Overview

Read a passage beside the reports, and distinguish an occasion from its wider context. Portfolio rank 18 of 20, independent project `apps/revelation-context-explorer`. Published with static Cloudflare Pages hosting at https://revelation-context-explorer.moongazer.tech/.

## Goals and visitor flow

Choose a passage or report category. Read the complete selected ayahs, the narrator-attributed report summary, what it establishes and its explicit limitations. Compare a relationship classification, follow two exact commentary links, then save or print a dossier.

Keep the complete activity usable immediately without an account, personal history, paid inference or a live API. All runtime content/fonts and interactions are local. Explicit bookmarks and temporary recovery are optional.

## Features and content

- `readings`: 10 records.

There are 41 exact source-list entries, 14 generated HTML pages, source/privacy/404 routes, print controls, both themes and a clear-data dialog. The app has its own manifest, lockfile, fonts and license files.

## Scope and limits

Ten readings include seven transmitted occasions, one general-context record and two responses after revelation. A response must not be relabeled as a cause. Narrator and date uncertainty remain visible. Collection attribution is not independent chain grading. Al-Muyassar notes and full Arabic Ibn Kathir links do not create an invented scholarly consensus.

Ten selected passages pair canonical text with a named Sahih al-Bukhari report and links to fetched Al-Muyassar and full Arabic Ibn Kathir commentary. Transmitted occasions, general context and responses after revelation are kept distinct. Reliability labels identify the collection and do not independently regrade chains. A parallel account and retained narrative uncertainties prevent the selected report being mistaken for exhaustive history. Commentary notes and report summaries are original concise English paraphrases; no modern English hadith translation is republished.

Accounts, databases, user identity, external runtime assets, synchronized multiplayer and automatic publication are outside this implementation.

## Success criteria

Core flows work with empty or blocked storage. Activity logic, source integrity and route links pass verification. Both themes fit desktop and mobile widths with keyboard/native controls. `bun run check`, `bun test` and `bun run build` succeed independently. The release archive contains static files at its root.
